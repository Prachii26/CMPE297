# Decisions

One line per call I made without asking. Newest at the bottom.

- **Folder name is `assignment3`, lowercase.** The existing folders on disk are `assignment1` and `assignment2`, both lowercase, and the brief said to match that style.
- **Cloned the reference repos with `git clone` over HTTPS, not `gh`.** `gh` is not installed on this machine and installing it needed admin rights; all five repos are public, so plain `git clone --depth 1` reaches the same commits.
- **Added `*.db` to the root `.gitignore`.** The SQLite files for agents C and E are generated by a seed function on first run, so committing them would just create merge noise.
- **Screenshots are captured with Playwright+Chromium from a throwaway venv in `_reference/.shotenv`.** Keeps the browser dependency out of every agent's `requirements.txt` while still producing real screenshots of the dev UI, and `_reference/` is already gitignored.
- **Ran `adk telemetry disable` once.** The dev UI's consent modal covered the trace in the first screenshot attempt; disabling it is also the honest default for a graded assignment.
- **Agent C: unshallowed the `adk-samples` clone to read the deleted sample.** `software-bug-assistant` was removed from upstream `main` during a repo restructure, so I read it at the parent of the commit that deleted it (`fd9b4fe^`) rather than substituting a different sample.
- **Agent C: dropped the upstream vector/semantic ticket search.** It needed an embedding model and a vector store; a `LIKE` match plus real triage ranking keeps the agent dependency-free and the ranking is the part the brief asked us to change. Logged as a known limit in the agent README.
- **Free-tier Gemini quota is 20 requests/day on this key, and it governs the whole assignment.** Hit `429 RESOURCE_EXHAUSTED ... quotaId: GenerateRequestsPerDayPerProjectPerModel-FreeTier, quotaValue: 20` for `gemini-2.5-flash` (there is also a 5/minute cap). `gemini-2.0-flash` and `gemini-2.5-flash-lite` both return 404 "no longer available", so there is no alternate model bucket to fall back on. Plan: build every agent and its full test suite offline, keep all tests model-free, and spend the daily quota on exactly one live demo run per agent.
- **Every agent's model is built with `HttpRetryOptions(http_status_codes=[429,503,504])` and long backoff.** A multi-agent pipeline issues 5-10 calls in a burst, which trips the 5/minute cap immediately; retrying with backoff is the difference between a pipeline that runs and one that dies halfway.
- **No agent mixes the built-in `google_search` with any other tool on the same `LlmAgent`.** Verified against ADK 2.13.0 source (`llm_agent.py::_convert_tool_union_to_tools`): ADK only auto-wraps `google_search` into an internal agent tool when `bypass_multi_tools_limit=True`; with the default `google_search` singleton it is sent as a raw built-in alongside the function declarations, which Gemini rejects. Researchers therefore use `google_search` as their only tool, and any agent that needs both search and a function tool gets the search agent wrapped in `AgentTool`.
- **Kept `SequentialAgent`/`ParallelAgent`/`LoopAgent` even though ADK 2.13.0 deprecates them in favour of `Workflow`.** The brief names these three classes explicitly, they still work, and the deprecation warning itself says "Workflow cannot yet be used as an LlmAgent sub-agent", so migrating would break the composition. Noted in agent A's README.
- **Agent A: `{critique?}` rather than `{critique}` in the scorer prompt.** The offline pipeline test caught a real crash: on the first critic-loop iteration the key does not exist yet and ADK raises `KeyError: Context variable not found`. The `?` suffix makes it render empty instead.
- **Agent B: set `GEMINI_CLI_TRUST_WORKSPACE=true` on the CLI subprocess only.** Gemini CLI 0.66 exits 55 with "not running in a trusted directory" and the documented headless escape is this env var or `--skip-trust`. The env var is the narrower of the two, it is scoped to the child process, and `cwd` is already pinned inside our own sandbox. This is workspace trust, not tool auto-approval: no `--yolo` and no `--approval-mode` are ever passed.
- **Agent B: kill the CLI's whole process tree on timeout, not just the child.** `subprocess.run(timeout=120)` killed `gemini.cmd` but its `node.exe` grandchild survived holding the stdout pipe, so the follow-up `communicate()` blocked and a 120s timeout took over 400s. Now uses `Popen` with `CREATE_NEW_PROCESS_GROUP` plus `taskkill /F /T`; measured 15.3s return on a 15s timeout with zero orphaned processes.
- **Added `*.fixed.py` to the root `.gitignore`.** Agent D writes patch candidates beside the original file; they are generated output, not source.
- **Screenshots and demo transcripts are captured from the same live run.** The Playwright script sends the query through the dev UI, then `dump_session.py` reads that same session's events back from the ADK API. A separate run just to produce a transcript would double the API cost, and one run of agent A is already 7-11 of the 20 daily requests.
- **Validated agent D's fix loop is winnable before spending quota on it.** A hand-written decomposition of `samples/buggy_module.py` takes complexity from 16 to 8 and style violations from 24 to 0, so `checks_pass` can genuinely become true. Worth knowing the thresholds were achievable before asking a model to hit them.
- **Switched every agent's default model to `gemini-flash-latest`** after the user confirmed `gemini-2.5-flash` was their preference rather than an assignment requirement. The daily quota is tracked per model (`GenerateRequestsPerDayPerProjectPerModel`), and probing the key found six usable alternatives; `gemini-2.5-pro` and `gemini-2.5-flash-lite` return 404 for this key. Each `docs/demo.md` records the model that produced its transcript.
- **Agent B: implemented `GEMINI_CLI_USE_OAUTH`, but it cannot be used with the cached account.** Setting it strips `GEMINI_API_KEY`/`GOOGLE_API_KEY` from the child env and sets `GOOGLE_GENAI_USE_GCA=true`, which is what actually selects "Login with Google" (with a key present the CLI always prefers it, and with no key and no `USE_GCA` it exits 41 demanding an auth method). The cached credentials then fail with `IneligibleTierError: Your current account is not eligible for Gemini Code Assist for individuals`, which is what Google returns for managed/Workspace accounts. The flag stays in the code and is documented; the default is off, so agent B runs on the API key.
- **Stopped running agents concurrently.** Agent A's three parallel researchers plus agent D plus agent B's CLI exceeded the per-minute cap and produced self-inflicted 429s. The retry config absorbed them, but serialising the demo runs is faster overall.
- **Screenshot completion is detected by polling the ADK sessions API, not the DOM.** During a 429/503 backoff the dev UI is completely static, so a "page stopped changing" heuristic reads as finished and closing the browser cancels the run server-side (`Root node ... was cancelled`). Two real runs were lost that way before the detection moved server-side.
- **Gave each of agent A's three researchers its own model.** Quota is per model, and three simultaneous researchers on one model is an instant 429 that the whole pipeline then waits behind. This did not rescue agent A (the real blocker turned out to be grounding), but it is the right shape for a parallel stage and is kept, configurable via `LEAD_RESEARCH_RESEARCHER_MODELS`.
- **Agent A is PARTIAL: Google Search grounding is rate limited separately from the model, and is exhausted on this key.** Proved by a controlled test on one model in one minute: a plain request returns 200, the same request with `tools: [{google_search:{}}]` returns 429. The giveaway is the error shape, since per-model 429s carry a `QuotaFailure` detail naming `GenerateRequestsPerDayPerProjectPerModel` while the grounding one carries only a `Help` link. Not worked around by dropping `google_search`, because a research agent without search would produce leads from memory with invented source URLs, which is exactly what the critic exists to reject.
- **Agent D: `propose_patch` now fails a patch that changes the public API.** A live run returned `checks_pass: true` for a patch that was style-clean and under the complexity threshold and had replaced the module's whole discount feature. Style and complexity cannot see semantics, so the API comparison is the cheapest available proxy; private helpers are exempt so decomposition still works.
- **Agent D: `check_style` now returns the source line for every violation.** The same run showed the reviewer inventing variable names (`is_holiday`, `is_birthday`) for lines it had only metadata about; those names then seeded the fixer's rewrite. Showing the line removes the need to guess.
- **Agent A: replaced the built-in `google_search` with a `web_search` FunctionTool backed by DuckDuckGo (`ddgs`).** Search grounding is metered separately from the model and is exhausted on this key, so no choice of model could get the parallel stage running. DDG needs no key and no quota. The architecture the assignment asks for — Sequential/Parallel/Loop, `output_key` state passing, a critic that rejects unsourced leads — is independent of which engine sits behind the tool. Researcher prompts and the critic are unchanged, and the critic still requires a real source URL per lead.
- **Agent A: kept the `AgentTool` wrapper around the critic's search agent even though it is no longer required.** It existed because `google_search` is a built-in that Gemini refuses alongside function declarations; a `FunctionTool` has no such restriction. Kept because it is the composition the assignment asks to demonstrate and it keeps the critic's verification on its own budget.
- **Agent A: DDG throttles a three-way burst with HTTP 202 and an empty body rather than an error.** First live run measured 4 usable responses against 15 rate-limited ones at a 1.5s inter-call gap. The tool now serialises calls behind a 6s gap, treats an empty result set as retryable rather than as "nothing found", and retries 4 times with jittered backoff.
